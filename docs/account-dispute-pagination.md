# Sandbox account dispute pagination

The account importer now follows PayPal's sandbox dispute-list pagination token through up to ten pages, checks for duplicate or invalid page tokens, and retrieves each listed dispute's details with four concurrent read-only requests. The adapter accepts a next link only when it points to PayPal's sandbox dispute-list endpoint, and never exposes the token in the import result. It reports incomplete listings, invalid pagination and failed details as unverified. Persona source IDs include only disputes whose PayPal detail names the source transaction as a seller transaction.

The [PayPal dispute API specification](https://github.com/paypal/paypal-rest-api-specifications/blob/main/openapi/customer_disputes_v1.json) documents the next-page token and link. PayPal's listing may lag or omit records. Even a completed listing cannot prove account-wide absence of a dispute or a complete refund history. The report, persona customers, request mutations, approved returns and scenario dispute state retain the qualifications in the account importer.

On November 11, 2026 UTC, a live read-only run against the connected sandbox retrieved 23 eligible reporting transactions and nine dispute-list pages containing 424 distinct disputes; all 424 details were retrieved. One generated persona cited capture `5BL31462HS946980L`, related report record `07S79917R7949050A`, and linked dispute `PP-R-FZC-10199004`. PayPal reported the dispute as `RESOLVED` for USD 50.00 and its detail linked the capture as seller transaction. The compact [evidence](evidence/account-dispute-pagination.json) contains only sandbox identifiers and sanitized fields. The import took approximately 88 seconds on this account; the amount of time grows with the number of dispute details. No real money moved.
