# Driving test upgrade: acceptance evidence

Updated 2026-11-11. The upgrade is incomplete. Sandbox evidence below is distinct from the deterministic mock; neither synthetic personas nor these trials establish real-world failure rates.

| Acceptance | Status | Evidence and limits |
| --- | --- | --- |
| $100 retry leak and stable request ID against PayPal | Passed in sandbox | [Sanitized evidence](evidence/sandbox-retry.json) records two distinct HTTP 201 $50 refunds on one $100 capture for the buggy run. The fixed run uses the same request ID and receives HTTP 201 then HTTP 200 for the same refund ID. PayPal subsequently reported the buggy capture as refunded and the fixed capture as partially refunded. The agent timeout was injected, not an actual network failure. |
| Open dispute rule with a real sandbox dispute | Passed in sandbox | [Sanitized evidence](evidence/sandbox-dispute.json) shows PayPal returned HTTP 201 for a $50 refund while the linked dispute was `UNDER_REVIEW`. | 1,000 public-data persona variants and repeated trials | Passed in mock | The driving-test browser ran 1,000 personas × 5 trials for each scripted agent. The generator cites 2,022 public records. Browser batch `446f8ec5-570f-46e3-818b-022f50080730` completed 5,000 scripted mock trials with this pool. Personas and behaviors are synthetic. |

The local HTTP example ran 5,000 trials before and after an identity-rule fix: batches `6e98cf87-0b81-45ec-b929-71a3726e6efb` and `9f82c08f-dd0f-4edd-acd6-16adda008cbf` showed 575 failures and zero failures respectively. |

A separate [recorded-case comparison](observed-agreement.md) reports 3 of 3 cases agreeing; it is not the required random sample or replay of every failure. Fresh approved captures and trusted complete refund history are required; checkout state is not restart-safe. See [refund-history](refund-history.md). |
