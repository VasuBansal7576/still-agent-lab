# Driving test upgrade: acceptance evidence

Updated 2026-11-11. The upgrade is incomplete. Sandbox evidence below is distinct from the deterministic mock; neither synthetic personas nor these trials establish real-world failure rates.

| Acceptance | Status | Evidence and limits |
| --- | --- | --- |
| $100 retry leak and stable request ID against PayPal | Unverified | Both flows are implemented and were exercised against a labeled synthetic provider fixture. Two new $100 sandbox captures and buyer approval are needed to observe real responses and resulting state. |
| Open dispute rule with a real sandbox dispute | Unverified | No sandbox dispute was created; buyer-side dispute creation is a human-only blocker. |
| 1,000 public-data persona variants and repeated trials | Passed in mock | The driving-test browser ran 1,000 personas × 5 trials for each scripted agent. The current generator cites 23 public records and produces synthetic variants; it does not contain 1,000 independent source records. Browser batch `38049a59-9417-466f-876c-96aee9dad743` completed 5,000 scripted mock trials. |
| Reliability and failure map | Passed in mock | CLI and browser show pass@1, pass^5, and failure clusters. `still test --personas 1000 --trials 5` gave 5,000 passes; `--agent buggy` gave 5,000 failures across duplicate, dispute, identity, missing amount, and approved-return clusters. Scripted trials are deterministic. The local HTTP example ran 5,000 trials before and after an identity-rule fix: batches `6e98cf87-0b81-45ec-b929-71a3726e6efb` and `9f82c08f-dd0f-4edd-acd6-16adda008cbf` showed 575 failures and zero failures respectively. |
| Real sandbox replays and agreement | Unverified | A replay plan, durable reservation ledger and receipt reconciliation exist. They are not wired to a live replay execution journey. No qualifying replay or agreement score exists. Fresh approved captures and trusted complete refund history are required. See [refund-history](refund-history.md). |
| Earned permission enforced on replay | Partial | The browser generated a USD mock-only grant from batch `38049a59-9417-466f-876c-96aee9dad743`, blocked an amount above its ceiling, permitted an eligible amount and replayed those decisions. A failing batch receives no grant. No sandbox permission has been earned. |
| Toolkit/MCP agent connects | Partial | An MCP stdio client connected to the demo mock gateway and exercised a grant with `node examples/toolkit-client.mjs --demo`. The grant belongs to a scripted trial, not the client. The v2 local HTTP example ran through the browser. Full compatibility with an actual PayPal Agent Toolkit agent and its own earned grant remain unverified. |
| Shadow session promoted and rerun | Passed for mock example | Browser recorded, promoted and reran mock regression `b4a4d517-590b-4710-a269-2915a71a9d3f`, including a blocked refund. Recording a real agent's live session is unverified. |
| CLI and GitHub Action | Passed in mock | Local 1,000 × 5 CLI run passed. [GitHub Actions run 43058554096](https://github.com/VasuBansal7576/still-agent-lab/actions/runs/43058554096) completed successfully for commit `9156124`. |
| Public repo, license, setup and judge replay | Partial | LICENSE and setup exist. [Hosted read-only replay](https://still-sandbox-replay-vasu.zippy17.chatgpt.site) displays earlier $50 real sandbox traces; it does not prove the new $100 case. [Public repository](https://github.com/VasuBansal7576/still-agent-lab) was synchronized at commit `9156124`. |
| Connected-account personas | Unverified | Read-only import was exercised with synthetic provider responses; incomplete reports return no personas. The browser reports no connected sandbox account, so actual account import remains unverified. |

Earlier $50 sandbox traces show an already-refunded capture being rejected with HTTP 422 and the corrected scripted flow avoiding the duplicate. They are not evidence for two successful partial refunds.
