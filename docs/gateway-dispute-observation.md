# Sandbox gateway dispute observation

Before reserving or sending an eligible refund, the sandbox earned-permission gateway requests PayPal's disputes filtered by capture ID. A failed or malformed response, an incomplete page, an unidentifiable dispute, or a dispute whose detail cannot be verified as resolved for the same capture blocks the request. The lookup is sandbox-only. An empty list is reported as an observation, not verified proof that no dispute exists; provider visibility can lag. The controlled scenario still uses synthetic store approval and identity, and complete external refund history is not established.

On November 11, 2026 UTC, Still derived a GBP permission from passing batch `d0c88817-eae0-471a-93d1-571fdd77f8ca` and its authenticated sandbox replay. A direct call through the actual gateway supplied a synthetic store context for existing sandbox capture `61P8728657149900M` and an explicit GBP 1.00 refund request. The gateway queried PayPal and returned `blocked: true` with `PayPal reports an unresolved or unverifiable dispute for the capture.` The reservation function was not called and no refund was sent. PayPal also reported the capture as `PENDING`, which independently would have prevented a refund. The same lookup for capture `5DC927363V559625J` returned no unresolved dispute, without establishing absence. These are sandbox observations, not production authorization proof.

The integrated browser journey was also run on a freshly started server with the saved sandbox connection. [Sanitized saved evidence](evidence/sandbox-gateway-dispute-lookup.json) records an over-limit denial, capture `6YP526519T197664M`, and PayPal HTTP 201 for refund `8JA19458HG642044S` of USD 50.00. PayPal returned `PENDING`, so the run remains unverified. The eligible result includes `disputeObservation`, which explicitly does not claim that the empty listing proves no dispute exists.
